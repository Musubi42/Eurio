Notes design
  • Pourquoi full-page — un drawer 85vw rend les raws eBay (1500-3000px de large) trop petits pour vérifier visuellement les détections. Le user fait un listing à la fois → pas besoin de voir la grille derrière. Esc/← retourne à la grille.
  • Pourquoi stage 1+2 superposés (et pas tabs/accordion) — l'overlay de cercles n'a aucune utilité sans le raw dessous. Toggle d'opacité (D) permet de basculer rapidement entre "voir la photo" et "voir l'analyse". Tabs forcerait un changement contextuel, accordéon doublerait la hauteur. La superposition garde la lecture cohérente.
  • Tags numérotés — chaque cercle détecté a un tag (1-N) qui apparaît aussi sur le crop card correspondant. Hover crop → cercle pulse 2× ; hover cercle → crop highlights. C'est le micro-mécanisme qui permet de remonter une mauvaise détection sans réflexion ("le crop flou en n°6, c'est lequel sur le raw ?").
  • Cercles rejetés (rouge dashed) — montrer ce que le pipeline a considéré et écarté = pure transparence. Évite que le user se demande "pourquoi cette pièce n'a pas été détectée". Annotation inline donne la raison (r < rmin, off_centre, etc.).
  • Bouton flag par crop — quand la détection est OK mais le crop foireux (cas b-6), l'utilisateur flag avec l'icône drapeau. État visuel inline. V1 = flag local ; V2 enverra ces flags à un endpoint pour collecter les cas où la pipeline doit s'améliorer.
  • Bulk via checkboxes — checkbox top-right du crop card. Sélection ≥1 → sub-footer indigo apparaît au-dessus du footer principal. Cohérent avec le drawer L.B+L.C actuel.
  • Layout adaptatif — case A (≤6 crops) = isolates en colonne unique 460px. Case B (≥7 crops) = isolates en grille 2 colonnes (540px), évite le scroll vertical infini. Le breakpoint peut être déclenché soit sur le nombre de crops soit sur la viewport disponible (à choisir, je préconise N>6).
