### C6a — Scraping → push_run — ✅ LIVRÉ opt-in (2026-06-29, `04bc433`)
- **Livré** : flag `--push` dans `ml/sources/cli.py` (PAS un straight-swap).
  Avec `--push` : pull réplique read-only (sans lease) → run pipeline écrit
  dans la réplique → `push_run(conn, run_id)` POST `/ingest/run`. Sans le flag :
  Modèle A inchangé (écrit la DB Mac). Garde `--push`⊥`--dry-run`. Couvre run
  principal + crop-pending.
- **Pourquoi opt-in** (et non straight-swap comme la spec initiale) : (1) la
  validation de parité **exige** que les deux modes coexistent pour comparer ;
  (2) évite un split-brain pendant la fenêtre C6 (recrop/dino/training pas
  encore migrés écrivent encore la DB Mac) ; (3) zéro régression du scraping
  quotidien tant que le PAT n'est pas posé. Le vrai cutover reste C8.
- **Vérifié ici** (sans serveur) : `export_run` lit un vrai run eBay de la
  réplique (9 tables, ~1400 lignes sur le graphe FK), `batch_sha` déterministe,
  `push_run` cible bien `/ingest/run`.
- **PAT + secrets** ✅ : `EURIO_API_URL` + `EURIO_API_TOKEN` (PAT scope
  `ingest:run`) ajoutés dans `secrets/dev.env` (SOPS/age, source unique — pas
  d'export manuel). Auth e2e OK (200 avec PAT, 401 sans).
- **Push e2e RÉEL** ✅ (2026-06-29) : push d'un vrai run (1428 lignes, 9 tables)
  via le client → Cloudflare → VPS → `/ingest/run` → APPLIQUÉ ; re-push
  idempotent (`already_applied`). Canonique live cohérent (run journalisé dans
  `ingested_runs`, 0 pointeur `image_state_current` pendant).
- **Fix `ingest_run` requis et livré** (`90cdd72`, déployé VPS) : le 1er push
  réel renvoyait **500**. Racine : `DELETE FROM image_state_events` violait la FK
  `image_state_current.last_event_id` (FK ON serveur ; invisible en local car
  `foreign_keys` OFF par défaut). Fix = `defer_foreign_keys=ON` + recalage de
  `image_state_current`. Cf. commit + test de non-régression `test_runbatch`.
- **CLI `--push` sur run eBay frais** ✅ (2026-06-29) : `go-task ml:src:run -- --source ebay --push --limit 1 --batch 1`
  (groupe CY/2012) → run complet (248 raws → 131 crops → dino → 78 enqueue) →
  `[model-b] push … → 1377 lignes appliquées`. Canonique live cohérent (run
  `a2ff9ffa…` journalisé, 251 source_images, 130 review_queue, 0 pointeur
  `image_state_current` pendant). **Note** : `--limit` cappe les *listings*, pas
  les images — `--limit 20` = ~1942 images (download+crop > 10 min). Pour une
  vraie passe, lancer dans un terminal (non borné par un timeout d'outil).
- **RESTE** :
  1. **Parité A↔B** ✅ **VALIDÉE + fix livré** (2026-06-29, `8d1fdf1`, déployé VPS).
     Méthode retenue (plus forte que comparer 2 runs live bruités) : comparaison
     **ligne-à-ligne déterministe** via `batch_sha` sur un run présent réplique **et**
     serveur (`f981e819`). Transport **fidèle, 0 perte**. Défaut trouvé : `run_id`
     de `source_images` était **last-writer-wins** → un run ultérieur volait
     l'attribution d'un run antérieur (re-scrape d'un groupe partagé : `f981e819`
     16-juin ↔ `a2ff9ffa` CY/2012 partageaient 3 images), cassant l'idempotence
     `batch_sha` du run volé. **Fix** : `run_id` first-seen immuable + table M:N
     `source_image_runs` (containment par-run) ; `export_run` scope via la junction ;
     backfill schema Mac + migration VPS `0003` (anti-orphelins). Post-fix VPS :
     f981e819 ré-exporte 195/197 (2 irrécupérables — aucun asset, dégât pré-fix ;
     pas de perte data), a2ff9ffa 251 intact. Vol **futur** éliminé.
     **Résidu assumé** : sha re-dérivé d'un vieux run peut varier si le contenu
     mutable (prix) d'une image partagée est rafraîchi plus tard — inhérent.
  2. **pytest** `tests/test_model_b_c2_c3.py` : bloqué sur `python-jose` absent
     du venv compute Mac (dép. serveur lean) — à lancer dans un env avec jose.
     (`tests/test_runbatch.py` 5/5 verts sur le Mac.)
  3. 🔴 **Dette séparée** : le canonique a **503 violations FK historiques**
     (`image_assets→source_runs` orphelins de prune non-cascade), identiques sur
     Mac/MinIO/VPS. `ingest_run` les tolère désormais, mais à **nettoyer** dans un
     chunk dédié (cf. C8 réconciliation).
  4. 🔴 **Bug `secrets/dev.env`** (préexistant, pas C6a) : `MINIO_ACCESS_KEY` y
     vaut une chaîne de 78 car. **erronée** (MinIO renvoie `InvalidAccessKeyId`)
