### C6a — Scraping → push_run — ✅ LIVRÉ opt-in (2026-06-29, `04bc433`)
- **Livré** : flag `--push` dans `ml/sources/cli.py` (PAS un straight-swap).
  Avec `--push` : pull réplique read-only (sans lease) → run pipeline écrit
  dans la réplique → `push_run(conn, run_id)` POST `/ingest/run`. Sans le flag :
  Modèle A inchangé (écrit la DB Mac). Garde `--push`⊥`--dry-run`. Couvre run
  principal + crop-pending.
- **Pourquoi opt-in** (et non straight-swap comme la spec initiale) : (1) la
  validation de parité **exige** que les deux modes coexistent pour comparer ;
  (2) évite un split-brain pendant la fenêtre C6 (recrop/dino/training pas
  encore migrés écrivent encore la DB Mac) ; (3) zéro régression du scraping
  quotidien tant que le PAT n'est pas posé. Le vrai cutover reste C8.
- **Vérifié ici** (sans serveur) : `export_run` lit un vrai run eBay de la
  réplique (9 tables, ~1400 lignes sur le graphe FK), `batch_sha` déterministe,
  `push_run` cible bien `/ingest/run`.
- **RESTE à valider (bloqué sur prérequis user/serveur)** :
  1. **Pré-PAT** (action user) : créer un PAT scope `ingest:run` via
     `eurio-admin.musubi.dev` (page « Mes tokens », chunk F7) ou la CLI
     `create-pat`, puis côté Mac : `export EURIO_API_URL=https://eurio-api.musubi.dev`
     + `export EURIO_API_TOKEN=eurio_…`.
  2. **Push e2e** : `go-task ml:src:run -- --source ebay --push --limit 100`
     (ou mock) → vérifier le bilan `[model-b] push … → N ligne(s)`.
  3. **Parité A↔B** : un run court Modèle A (sans `--push`, DB Mac) vs Modèle B
     (`--push`) ; comparer les comptages par table dans `source_runs` post-run.
     Doit être identique (sinon régression silencieuse `export_run`).
  4. **pytest** `tests/test_model_b_c2_c3.py` : bloqué sur `python-jose` absent
     du venv compute Mac (dép. serveur lean) — à lancer dans un env avec jose.
